# 設計と検証条件

## 現在

静的HTML/CSS/JSとNode.jsローカルサーバーのみ。認証、ストレージ、動画変換、DRMプレイヤー、ライセンス発行基盤は未接続。

## 目標の閲覧フロー

1. 所有者が書類・提出先・期限を指定する。
2. サーバー側で画像を動画化し、提出先識別子を映像に焼き込んで暗号化する。
3. 相手がURLを開き、指定メールの認証コードで本人確認する。
4. ライセンス要求ごとに、セッションと書類別の権限・期限・失効状態をサーバーで確認する。
5. 許可された環境だけに保護動画を表示する。エラー時は拒否する。

URLそのものを永続的な閲覧権限にはしない。元画像、未暗号化動画、サムネイル、暗号鍵は公開配置しない。クライアント側の表示切替や右クリック禁止は保護境界として扱わない。

## 保留事項

- 文書画像を配信する用途について、DRM事業者の許諾とApple等の要件を確認する。
- 価格、データ保持・削除、保管地域、再委託先、秘密情報管理を比較する。
- ソフトウェアDRMとハードウェアDRM、端末、OS、ブラウザー、表示経路による違いを実測する。
- 失効はライセンス更新時に効く場合がある。バッファ済みの映像や発行済みライセンスを含め、即時消去を保証しない。
- 画面の別端末撮影と、すでに持ち出されたコピーの回収は対象外。

## 実機テスト表

Windows ChromeとEdgeを最初の対象とし、後でSafariを追加する。

| 記録項目 | 確認内容 |
| --- | --- |
| 環境 | OS・ブラウザーの正確な版、GPU、外部モニター |
| DRM | provider、key system、robustness要求、実際の再生結果 |
| 可読性 | 氏名など小さい文字、拡大時、縦長書類の表示 |
| 静止画 | Print Screen、Win + Shift + Sなどの方法ごとに確認 |
| 録画 | 使用ソフト、共有・録画方式、映像が黒くなるか |
| 権限 | 別メール、未認証、期限切れ、失効後に新規ライセンスが拒否されるか |
| 継続再生 | 失効後に既存再生が止まるまでの時間 |
| 漏えい経路 | 元画像・サムネイル・未暗号化代替データが公開されていないか |

検証結果には必ずダミー動画のIDを含める。公開IssueやGit履歴にメールアドレス、書類画像、資格情報を添付しない。
